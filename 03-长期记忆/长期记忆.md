# cua-driver + Hermes computer_use 关键事实

## 架构层
- cua-driver 有两种运行模式：
  - `serve` 模式：daemon，单进程多客户端，socket 在 `~/Library/Caches/cua-driver/cua-driver.sock`
  - `mcp` 模式：stdio 子进程，被 Hermes `_CuaDriverSession` spawn 出来用
- Hermes `computer_use` 工具走的是 **mcp stdio 模式**，不是 daemon socket

## 重要限制
- **同一时间只服务一个 session**——14 个万手 bot + 主 agent 同时调会撞车
- 想给多 bot 用需要令牌机制（Redis / 文件锁），目前没实现
- 建议只给 1-2 个真有 GUI 需求的 bot（码农、Office 之类）

## 故障信号
- 报错 "cua-driver session not started" = Hermes 进程内 `_CuaDriverSession` 单例卡死（_started=False）
- 不等于 cua-driver daemon 出问题——daemon 健康也会出这个错
- 修复方法：重启 Hermes 主 gateway（launchd 会自动拉起）

## 已确认可工作的链路
- `cua-driver mcp` 子进程能起，33 个工具能调
- mcp 库在 venv 里能 import
- 修复后 `computer_use capture` 立刻返回真实屏幕 + AX 树

完整排查+修复 SOP 见 skill: cua-driver-session-troubleshooting
